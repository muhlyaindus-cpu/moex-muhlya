## План дообучения агента (D3QN + PER) под наш проект

Источник вдохновения: материал с Habr про D3QN + PER и практику на фьючерсах.  
Мы используем подход как **методологию**, но адаптируем под наш контур `MOEX + Finam`.

### 1) Данные
- Собираем OHLCV по акциям и фьючерсам MOEX (волатильные сессии отдельно отмечаем).
- Добавляем инженерные признаки:
  - RSI/MACD/ATR/объемные признаки
  - микро-структура: спред, прокси-ликвидность, волатильность.
- Формируем train/validation/test с walk-forward.

### 2) Среда (Gym)
- Действия: `buy/sell/hold` + ограничение позиции.
- Целевая награда: **рост баланса (equity/cash) в плюс**.
- Формула награды: `reward = прирост equity - издержки - штраф за риск`.
  - где издержки: комиссии + проскальзывание,
  - штраф за риск: drawdown/переторговка и др.
- Важно: агент максимизирует суммарную награду, значит при такой формуле
  он учится делать сделки, которые увеличивают баланс после всех реальных расходов.
- Риск-ограничения в среде:
  - max risk per trade
  - дневной лимит
  - штраф за частые flip-trades.

### 3) Модель и обучение
- Базовая линия: PPO (уже есть в `trading-lab`).
- Следующий шаг: D3QN + PER:
  - Dueling head
  - Double Q
  - Prioritized Experience Replay
  - soft target updates.
- Подбор гиперпараметров: Optuna / bayesian search.

### 4) Валидация
- Метрики:
  - Net PnL
  - Sharpe
  - max drawdown
  - win rate
  - turnover/cost efficiency.
- Обязательный out-of-sample и stress по разным волатильным периодам.

### 5) Интеграция с нашим Go-агентом
- Обучение остается оффлайн (Python).
- В прод передаем только “политику” (json-параметры поведения/фильтры), без тяжелого инференса.
- Риск-менеджер в Go всегда главный (hard guardrails).

### 6) Как подключить журнал сделок для дообучения
- Используем локальный `trades` журнал (реальные + paper сделки).
- Для каждого трейда сохраняем:
  - инструмент/сторона/цена/qty/время/статус.
- При retrain добавляем:
  - realized PnL по закрытиям
  - time-in-trade
  - реакцию модели на похожий контекст.

### 7) Практический порядок работ
1. Доработать экспорт датасета из локального журнала.
2. Поднять D3QN+PER baseline на одном инструменте.
3. Прогнать walk-forward на корзине MOEX.
4. Включить в прод только после paper-стабильности.
