# Мухля и Мия: роли, приоритеты и связка

Документ фиксирует **разделение ответственности** между торговым контуром (**Мухля**, `muhlya-headless`) и аналитическим модулем (**Мия**, inline в Go-коде). Цель — достижение **дохода 1-5% в день** при контроле рисков.

**Образ:** Мухля — **исполнитель** (ордера, риск, лимиты). Мия — **аналитик и штурман**: даёт срез рынка и контекст для решений, но не подменяет торговый контур и не выставляет заявки.

## Краткая таблица

| | Мухля | Мия |
|---|--------|-----|
| **Роль** | Исполнение, риск, брокер Finam | Аналитика: состояние рынка, ликвидность, контекст для гейтов |
| **Главный приоритет** | Сохранение счёта, доход 1-5%/день | Стабильный, проверяемый контекст рынка |
| **Горизонт времени** | Секунды–минуты (автоцикл ~30 сек) | Минуты (inline-запрос MOEX ISS каждые 30 сек) |
| **Режим работы** | Headless на VPS, systemd | Встроен в Мухлю (inline MIYA), без внешних скриптов |

## Зоны ответственности

### Мухля (обязательно здесь)

- Решения **вход / выход**, размер позиции, **TP / SL / profit lock**, дневные и прочие лимиты риска.
- Взаимодействие с **Finam** (заявки, портфель, журнал сделок).
- Ранжирование кандидатов на покупку (агент, confidence, исполнимость лота, история по тикеру в Postgres).
- **Синхронизация позиций** из Finam API при старте (`syncPositionsFromBroker`).
- **Форматирование цены** с правильным количеством знаков (GetDecimals из MOEX ISS).
- **Обработка ошибок** — cooldown при price limits (10032), money shortage (156), equities shortage (157).

### Мия (обязательно здесь)

- **Inline-режим** (`fetchMiyaInlineFromMOEX`) — запрос MOEX ISS для списка тикеров.
- Вычисление **состояния рынка**: `STATE` (bullish/bearish/neutral), `UP_RATIO_PCT`.
- **Ранг ликвидности** — сортировка тикеров по VALTODAY.
- **Watch-список** — список тикеров для приоритетного рассмотрения (`MIYA_WATCH_TICKERS`).
- **Не** выставляет заявки и **не** подменяет риск-менеджер.

### Как Мия помогает Мухле

- Мия поставляет **контекст рынка** через `miyaOnlineSignal`:
  - `State` (bullish/bearish/neutral) — сдвигает buy/short гейты
  - `UpRatioPct` — % тикеров с положительным изменением
  - `LiquidityOrder` — приоритет по ликвидности
  - `WatchTickers` — список для приоритетного рассмотрения
- Мухля **сама решает**, как этот контекст учитывать — через настройки `AGENT_MIA_ONLINE_*`:
  - `miya_buy_adj` — корректировка buy gate (bearish → сложнее покупать)
  - `miya_short_adj` — корректировка short gate (bearish → легче шортить)

## Цель: доход 1-5% в день

### Стратегия достижения

| Параметр | Текущий | Целевой | Обоснование |
|----------|---------|---------|-------------|
| **TP** | 1.8% | 1.5-2.0% | Частые мелкие прибыли |
| **SL** | 1.0% | 0.8-1.0% | Ограничение убытков |
| **Trailing** | 0.8%/0.5% | 0.6%/0.4% | Фиксация прибыли |
| **Conf threshold** | 0.55 | 0.50-0.55 | Больше входов |
| **Бюджет** | 100% | 80-95% | Резерв на проскальзывание |

### Как считаем доход

- **1% от 30,000₽ = 300₽/день** — нужно ~2-3 прибыльные сделки
- **5% от 30,000₽ = 1,500₽/день** — нужно ~5-8 прибыльных сделок
- Комиссия: 0.035% × 2 = 0.07% round-trip для акций
- Минимальный TP для безубыточности: ~0.1% (с учётом комиссий)

### Роль Мии в достижении цели

1. **Фильтрация входов** — bearish market → Мухля покупает осторожнее
2. **Приоритет ликвидности** — более ликвидные тикеры → меньше проскальзывание
3. **Watch-список** — приоритет проверенным тикерам

## Приоритеты задач (порядок важности)

1. **Надёжность и риск (Мухля)** — выше любого «красивого сигнала».
2. **Качество данных Мии** — осмысленный `DataStatus`, консистентный онлайн-сигнал.
3. **Доход 1-5%/день** — оптимизация TP/SL/Trailing для частых прибыльных сделок.
4. **Наблюдаемость** — отчёты и `runtime_events`, чтобы понимать «почему не вошли» / «почему вышли».

## Контракт данных

| Данные | Кто пишет | Кто читает | Примечание |
|--------|-----------|------------|------------|
| `miyaOnlineSignal` (в памяти) | Мия (inline) | Мухля | State, UpRatio, Liquidity, WatchTickers |
| Postgres `runtime_events` | Мухля | Мия (отчёты), человек | События автоцикла |
| Postgres `trades` | Мухля | Человек | Журнал сделок |
| Postgres `positions` | Мухля (sync из Finam) | Человек | Текущие позиции |
